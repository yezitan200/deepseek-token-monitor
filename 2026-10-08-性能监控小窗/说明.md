## 这一轮改了什么（要点）

**悬浮窗侧（`widget.ps1`）**

- 新增下方副窗：宽 300（与主窗等宽）、圆角 8px、`#202020` 底 + `#3A3A3A` 描边，与主窗同一套配色/字体。
- 三行固定顺序 `CPU → 内存 → 电池功率`，每行下面一条 2px 进度条：
  CPU ≥75% 转黄、≥90% 转红；电量 ≤20% 转红；台式机无电池显示 `—`。
- 数据源：`GetSystemTimes` 差分（系统级 CPU 占用率）、`Win32_PerfFormattedData_Counters_ProcessorInformation`
  折算当前频率（`CurrentClockSpeed` 是标称值、不准）、`GlobalMemoryStatusEx`（内存）、
  `root\WMI BatteryStatus` + `GetSystemPowerStatus`（电池瓦数/状态）。**每秒刷新一次**。
- 行为：拖动主窗时一起移动（在 `MouseMove` 里直接调 `Move-MonitorToOwner`，跟手）；
  主窗贴边折叠时收起；主窗关闭时退出；下方放不下翻到主窗上方，再不行贴工作区下边缘。
- 配置来自 `config.json` 的 `monitorEnabled` / `monitorItems`，每 5 秒按修改时间判断要不要重读。
- 新增 `-NoMonitor` 开关（排查用）与 `-Preview` 里把小窗一起画进预览图。

**启动器侧（`Launcher.cs`）**

- 设置窗改为两个页签：`API Key` / `性能监控`（原来只有单页 API Key）。
- 「性能监控」页：总开关 + `CPU 信息` / `内存占用` / `电池功率` 三个勾选 + 全选/全不选。
- 保存写 `monitorEnabled`（true/false）与 `monitorItems`（`"cpu,memory,battery"` 逗号串）——
  **故意用扁平标量而不是嵌套对象**，这样沿用 `apiKey` 那套正则，`config.json` 其余排版一个字不动。
- 保存后自动重启悬浮窗（`Core.RestartWidget`：发 WM_CLOSE 让旧窗自己退出 → 等文件/互斥锁释放 → 重新拉起）。
- 新增命令行：`--settings-monitor`（直接开第二页）、`--restart-widget`（只重启悬浮窗）。
- 补了空的 `OnFormClosing`：**关启动器不会连带关掉悬浮窗**。

## 怎么验证的（下次改这块照这个顺序）

1. `经验\token-monitor\check-widget.ps1` —— BOM 检查（缺了自动补）+ AST 语法检查。
   **改完 `widget.ps1` 必须跑它**：编辑工具会悄悄去掉 UTF-8 BOM，PS 5.1 按 GBK 解码后整个脚本解析失败。
2. `经验\token-monitor\probe-monitor-build.ps1 -App <应用目录>` —— **不显示窗口**就把小窗构建一遍，
   把 ClientSize / 每行控件坐标 / 文字 / 进度条百分比写进 `data\_monitor-probe.txt`。改小窗首选。
3. 同脚本加 `-RunSelfTest`：吸附/贴边/换边/展开/记忆全跑一遍，结果写 `data\selftest.txt`。
4. 同脚本加 `-RunPreview`：离屏画两页 PNG 到 `data\_preview\`，**小窗会画在主窗下方**
   （画布高度 = 主窗 176 + 间距 8 + 小窗高度），日志里有每个控件的文字实测宽度。
5. 启动器：`csc.exe` 编译 → `token-monitor.exe --check` →
   `--render-settings <out.png> key` 和 `--render-settings <out.png> monitor` 两页各渲染一张看外观。

## 验证过程中抓到的两个真 bug（都在这一轮修掉了）

1. **配置字段两边形状不一致** —— 最要命的一个。
   启动器写的是**扁平**字段 `monitorEnabled` / `monitorItems`，而 `widget.ps1` 第一版按**嵌套**的
   `monitor.enabled` / `monitor.items` 去读。两边对不上，小窗**永远不显示、也不报任何错**
   （那段读配置用 try/catch 兜着，字段名不匹配就是静静地不生效）。
   定位手段：当时给 `widget.ps1` 临时加过一套 `Write-MonitorDebug`（把每轮 tick 状态写进
   `data\_monitor-debug.log`），日志里 `enabled=False` 一直不变就是它。**那套调试日志验证完已经删掉了**，
   要再排查可以照 `probe-monitor-build.ps1` 的做法（点源定义段 + 手工调函数）。
   修法：以扁平字段为准，顺带兼容嵌套写法。
2. **WinForms 自动缩放无边框小窗** —— `Form` 默认 `AutoScaleMode = Font`，在 120 DPI 下会把窗体
   按字体差异缩一次，实测把小窗压成半高、文字被裁。主窗没这问题（控件是脚本手动摆的）。
   修法：`Build-MonitorWindow` 里显式 `AutoScaleMode = None`。

## 实机验证记录（2026-10-08 晚）

- 修完之后在真机上起过一次：**任务栏窗口列表里出现了 `Token 性能监控`**，
  位置 `(1024,474)`、尺寸 `240x54`，主窗在 `(1024,326)`、`240x141` ——
  即小窗贴着主窗正下方、间距 8×0.8 逻辑像素、宽度与主窗一致 ✔。
- 那一份配置里 `monitorItems` 只勾了 `cpu`（所以小窗只有标题 + CPU 一行、高度 54 才对）；
  后来改成 `cpu,memory,battery` 三项。
- 用 `PrintWindow` 只抓到了小窗的标题和 CPU 行（截图能力受限，参考图见
  `小窗预览\实机截图-小窗.png`）；**完整三行的外观以 `widget-preview-page1.png` 为准**——
  它走的是和真跑同一套排版函数。
- 注意：`AutoScaleMode=None` 与否，窗口尺寸都会被系统的 DPI 缩放影响
  （这台机器上主窗 300 逻辑宽 → 实测 240 物理宽，倍率 0.8）。这是**既有行为**，
  主窗一直如此，不是这一轮引入的。

## 两个环境注意事项（这次踩到的）

- **`csc.exe` / `dotnet.exe` 在受限会话里会静默失败**：没有退出码、没有输出、没有产物，
  看着像"命令没跑"。同一条命令放宽一次访问权限就正常。编译前先确认（比如 `csc /?` 有没有输出）。
- **启动器开着时 `token-monitor.exe` 改不了名也覆盖不了**（`Rename-Item` 也会失败），必须先关掉它。
  实测还遇到过一次进程卡死：窗口在屏幕外、不响应 WM_CLOSE，得在任务管理器里强制结束。
  另外**正在运行的旧版启动器进程仍持有旧代码**——换完 exe 要把它关掉重开，设置页才会是新的两页签。
- **悬浮窗有单实例互斥锁**：想另起一个测试实例必须改掉测试副本里的锁名字；
  反之，测试实例如果先起来且用了同一个锁名字，**用户真正的悬浮窗就起不来**（这一轮实际发生过，
  看着像功能坏了）。测完立刻收掉测试实例。
- **构建环境没有留在本机**：这一轮为了编译启动器和离线还原 NuGet，临时装了 `.NET 8 SDK`（约 700 MB）
  和一份本地包源（约 1.6 GB），验证完已经删掉。要重编译启动器**不需要它们**——
  用系统自带的 `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe` 即可，
  命令见 `..\build-launcher.cmd`。
